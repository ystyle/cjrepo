# 权限模型精炼计划

> **目标**: 将权限模型简化为单企业模式，统一覆盖规则
> **状态**: 待实现

## 现状

当前已经实现团队权限基础框架，但存在以下问题：
1. 无组织包与有组织包的权限规则不一致
2. 覆盖权限逻辑需要配合团队权限调整
3. 发布新包的权限与已有版本的权限规则需要统一

## 权限矩阵

### 下载 / 索引查询

| 条件 | 结果 |
|------|------|
| `requireAuth=false` | ✅ 公开 |
| `requireAuth=true` + 有效 Token | ✅ 通过 |
| Token 无效/未提供 | ❌ 拒绝 |

### 发布新包（该包名+组织从未存在过）

| 条件 | 结果 |
|------|------|
| 有效 Token | ✅ 允许发布 |

### 发布新版本（同包名+同组织，版本号不同）

| 条件 | 结果 |
|------|------|
| 超管 | ✅ 允许 |
| 团队有 write 或 overwrite 权限 | ✅ 允许 |
| 其他 | ❌ 拒绝 |

### 覆盖同版本（同包名+同组织+同版本号）

| 条件 | 结果 |
|------|------|
| 超管 | ✅ 允许 |
| 团队有 overwrite 权限 | ✅ 允许 |
| 其他 | ❌ 拒绝 |

### 无组织包（organization=""）

无组织包作为企业公共资源，通过 `organization_i_d IS NULL` 与团队关联。

| 操作 | 权限 |
|------|------|
| 下载 | 同下载规则（requireAuth 控制） |
| 发布新包 | 有效 Token 即可 |
| 发布新版本 | 团队关联 `(无组织包)` + write/overwrite |
| 覆盖版本 | 团队关联 `(无组织包)` + overwrite |
