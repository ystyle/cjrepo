# 发布计划

发布计划功能允许用户将私有仓中的包批量发布到上游中心仓（如 pkg.cangjie-lang.cn），自动分析依赖树并按正确顺序发布。

## 场景

多包项目发布困难是常见痛点：
- 包之间存在依赖关系，需要按顺序逐个发布
- 发布后需要等待上游索引更新才能继续下一个
- 依赖版本冲突难以排查
- 手动操作容易出错且耗时

发布计划自动处理依赖分析、版本对比、索引轮询，简化多包发布流程。

## 前提

1. 已配置上游源（[上游代理](/guide/upstream)），指向官方中心仓或其他 cjrepo 实例
2. 上游源已配置发布 Token，有权限向目标仓发布包

## 创建发布计划

点击左侧菜单「发布计划」→「新建计划」，进入三步向导。

### 步骤 1：选择起始包

![步骤1](/assets/admin_publish_step1.png)

- 选择目标上游（发布到哪个中心仓）
- 输入起始包，格式：`组织::包名@版本`（有组织）或 `包名@版本`（无组织）
- 支持添加多个起始包

### 步骤 2：分析依赖

![步骤2](/assets/admin_publish_step2.png)

点击「分析依赖」，系统会自动：
1. 递归解析各包的依赖树
2. 去重合并
3. 与上游中心仓对比版本和 SHA256

分析结果按分类分组：

| 分类 | 说明 | 默认操作 |
|------|------|---------|
| 🔴 冲突 | 版本号相同但 SHA256 不一致 | 需确认是否覆盖 |
| 🔴 需要发布 | 中心仓缺失该版本 | 默认选中 |
| 🟡 可选版本 | 依赖范围内有多个版本可选 | 用户勾选 |
| ⚪ 已存在 | 版本和 SHA256 与中心仓一致 | 跳过，不可选 |

### 步骤 3：确认并创建

![步骤3](/assets/admin_publish_step3.png)

- 确认发布顺序（系统按依赖拓扑排序）
- 输入计划名称
- 可调整轮询间隔和超时时间
- 确认创建

## 查看执行状态

从列表页进入详情页，实时查看发布进度。

![列表](/assets/admin_publishplan.png)

![详情](/assets/admin_publish_view.png)

**实时更新机制**：
- 使用 SSE（Server-Sent Events）推送状态变更
- 同时每 60 秒轮询兜底，确保不遗漏更新

**状态说明**：

| 状态 | 图标 | 说明 |
|------|------|------|
| pending | ⏳ | 等待发布 |
| publishing | 🔄 | 正在发布到上游 |
| waiting_index | ⏳ | 等待上游索引更新 |
| completed | ✅ | 发布完成 |
| failed | ❌ | 发布失败 |
| skipped | ⏭️ | 已跳过 |

## 计划控制

- **开始**：确认后手动触发执行
- **暂停**：暂停执行中的计划
- **继续**：恢复已暂停的计划
- **删除**：删除已完成或失败的计划

## 配置说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 轮询间隔 | 60 秒 | 每次轮询上游索引的等待时间 |
| 超时 | 自动计算 | 总超时 = 包数 × 间隔 × 5 × 2 |
